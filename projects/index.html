Nine projects. Three difficulty levels. All hands-on.

Every project pairs with a module from one of the three tracks and targets an intentionally vulnerable, legal practice environment — never a live system you don't control. Filter by level, or just work through them top to bottom.

Beginner

Foundations in practice

~/projects/nmap-scan
Beginner

Your first Nmap scan

Discover what's actually running on a lab target before you ever try to attack it.

⏱ 30–45 min ✓ Beginner module 6
NmapVirtualBox
  1. Boot Kali and a target VM (Metasploitable or DVWA) on the same Host-only network
  2. Confirm the target's IP address from within the target VM itself (ip a)
  3. From Kali, run nmap -sV -sC <target-ip>
  4. Save the output with -oN first-scan.txt
  5. Write 3–4 sentences: what's exposed, and why each open port matters
~/projects/wireshark-capture
Beginner

Wireshark packet capture

See exactly what a network conversation looks like at the byte level.

⏱ 30–45 min ✓ Beginner module 6
Wiresharkcurl
  1. Open Wireshark on Kali and start a capture on the Host-only interface
  2. From a second terminal, ping and then curl http://<target-ip> the target VM
  3. Apply the display filter ip.addr == <target-ip>
  4. Right-click an HTTP request → Follow → TCP Stream
  5. Note what's readable in plaintext, and why HTTPS would change that
~/projects/dvwa-setup
Beginner

Set up DVWA

Stand up your own legal web-app target that every later web project will reuse.

⏱ 45–60 min ✓ Beginner module 5–7
DockerDVWA
  1. Install Docker on your target VM (or a dedicated third VM)
  2. Pull and run a DVWA image, e.g. docker run -d -p 80:80 vulnerables/web-dvwa
  3. Browse to the target's IP from Kali and complete the DVWA database setup screen
  4. Log in with the documented default DVWA credentials, then set the security level to "low" for practice
  5. Confirm you can reach it from Kali only — never expose it beyond your lab network
Intermediate

Core toolset in practice

~/projects/burp-exploitation
Intermediate

Burp Suite exploitation

Find and exploit a broken access control issue in DVWA using a proxy, not guesswork.

⏱ 1–2 hrs ✓ Intermediate module 3
Burp SuiteDVWA
  1. Point your browser's proxy at Burp and install its CA certificate
  2. Log into DVWA's "Insecure Direct Object Reference" module as a low-privilege test account
  3. Intercept a request containing a user or record ID parameter
  4. Send it to Repeater and change the ID to a different value
  5. Document what data you can access that you shouldn't be able to, and why
~/projects/hydra-brute-force
Intermediate

Hydra brute force

See exactly how fast a weak password falls, then see how much a strong one changes that.

⏱ 45–60 min ✓ Intermediate module 4
HydraSSH
  1. On your target VM, create a test user with a weak password taken from a small local wordlist
  2. Confirm SSH is running: systemctl status ssh on the target
  3. From Kali, run Hydra against that user with the same wordlist
  4. Record how long it took to find the correct password
  5. Reset the account to a long, random passphrase and note why Hydra would no longer succeed in a practical timeframe
~/projects/metasploit-exploitation
Intermediate

Metasploit exploitation

Use a real framework exploit to land your first shell on Metasploitable.

⏱ 1 hr ✓ Intermediate module 2
MetasploitMetasploitable
  1. Scan the Metasploitable VM with Nmap and note the FTP service and version
  2. In msfconsole, search for and select the matching backdoor exploit module
  3. Set RHOSTS and LHOST, then run the exploit
  4. Confirm your access level with whoami in the resulting shell
  5. Write down what a real attacker could do next from this position
Advanced

Capstone-level builds

~/projects/buffer-overflow
Advanced

Buffer overflow exploitation

Work a classic stack overflow end to end, in a fully isolated debugger lab.

⏱ 4–6 hrs ✓ Advanced module 3
Immunity Debuggermona.pymsfvenom
  1. Set up an isolated Windows lab VM with a purpose-built vulnerable TCP app and Immunity Debugger + mona.py attached
  2. Fuzz the application from Kali until it crashes, and note the crash state
  3. Generate a cyclic pattern to find your exact EIP offset
  4. Identify bad characters, then find a reliable JMP ESP address
  5. Generate shellcode with msfvenom and assemble a final proof-of-concept script
  6. Confirm a reverse shell lands on a listener on your Kali VM, then write up every step
~/projects/reverse-engineering
Advanced

Reverse engineering challenge

Recover the hidden logic of a small CTF-style binary using static and dynamic analysis.

⏱ 2–4 hrs ✓ Advanced module 2
GhidraGDB
  1. Download a beginner "crackme" binary from a legal practice source (crackmes.one, picoCTF reversing category)
  2. Run file and strings to get a first read on what it is
  3. Load it into Ghidra and let it auto-analyze, then read the decompiled main function
  4. Identify the comparison or key-check logic that decides success or failure
  5. Confirm your theory dynamically in GDB by breaking at that comparison and inspecting registers
  6. Recover the expected input and document how you found it
~/projects/ad-pentest
Advanced

Active Directory pentest

The capstone: build a small AD lab and run the full five-phase methodology against it.

⏱ 8–12 hrs ✓ Advanced module 7
Windows Server evalMetasploitenum4linux
  1. Build a 3-machine lab: a Windows Server domain controller, a Windows workstation joined to the domain, and your Kali attacker VM, all on an isolated Internal Network
  2. Recon & enumerate the domain with Nmap and enum4linux from Kali
  3. Find and exploit an initial foothold on the workstation using an intentionally weak configuration you set up (e.g. a weak local account)
  4. Escalate privileges and harvest local credentials from the workstation
  5. Pivot from the workstation to reach the domain controller and demonstrate domain-level impact
  6. Write a short report: executive summary, findings with severity, and remediation steps — following the format from the methodology module
