01

What Kali Linux is

Kali Linux is a Debian-based operating system built specifically for penetration testing, digital forensics, and security research. Instead of hunting down and installing tools one by one, Kali ships with hundreds of them — network scanners, password crackers, wireless attack suites, exploitation frameworks, and forensic utilities — already installed and organized by task.

It's maintained by Offensive Security, the organization behind the OSCP certification, and it's released on a rolling-release model, meaning tools update continuously rather than in big yearly jumps.

Why not just use regular Linux?

  • Security tools are pre-installed, patched, and organized by category out of the box
  • The desktop, menus, and defaults are tuned for security work rather than everyday computing
  • It includes special modes like Forensics Mode (avoids touching the host's disks) and Kali Undercover (disguises the desktop to look like Windows)
  • It's the de-facto standard in security courses, so guides and write-ups assume you're using it

Who actually uses it

  • Professional penetration testers and red teamers, under signed contracts
  • Security students working through certifications like OSCP, CompTIA PenTest+, or eJPT
  • CTF (Capture the Flag) players in competitions like picoCTF or HackTheBox
  • Security researchers doing malware analysis or vulnerability research

Kali is a toolbox, not a shortcutOwning a lockpick set doesn't make you a locksmith. Kali gives you the tools; this hub teaches you how, when, and — most importantly — where it's legal to use them.

02

Installing Kali on VirtualBox

Every project on this hub assumes Kali is running inside a virtual machine, not installed directly on your everyday computer. A VM gives you a disposable, snapshot-able lab: if you break something, you roll back in seconds, and nothing you do inside it touches your real files or network.

What you'll need

  • VirtualBox (free) installed on your host computer, from virtualbox.org
  • Virtualization enabled in your BIOS/UEFI (Intel VT-x or AMD-V)
  • At least 4 GB of RAM and 20 GB of disk space to allocate to the VM
  • The official Kali VirtualBox image from kali.org/get-kali (choose the pre-built ".OVA" appliance, not the bare ISO, to save setup time)

Install steps

  • Download the Kali "Virtual Machines → VirtualBox 64-bit" image from the official Kali site
  • In VirtualBox: File → Import Appliance, then select the downloaded .OVA file
  • Before finishing the import, bump RAM to 4096 MB+ and CPUs to 2 if your host can spare it
  • Set the network adapter to Host-only or Internal Network for now — you'll learn why in the networking module
  • Start the VM and log in with the default credentials on official post-2020 images: kali / kali
  • Immediately take a VirtualBox snapshot named "clean install" so you always have a safe rollback point

Snapshot before every projectGet in the habit of taking a fresh snapshot before starting each new project in this hub. If a tool misconfigures something, you're one click from a clean slate instead of a reinstall.

03

Basic Linux terminal commands

Almost every security tool in Kali is run from the terminal, so comfort with the shell is the single highest-leverage skill in this whole track. These are the commands you'll type dozens of times a day.

Moving around the filesystem

bash
$ pwd                    # print current directory
$ ls -la                 # list all files, including hidden ones
$ cd Documents/          # move into a folder
$ cd ..                  # move up one level
$ mkdir lab-notes        # create a new folder

Working with files

bash
$ touch scan.txt         # create an empty file
$ nano scan.txt          # edit a file in the terminal
$ cat scan.txt           # print a file's contents
$ cp scan.txt backup.txt # copy a file
$ mv backup.txt old/     # move (or rename) a file
$ rm old/backup.txt      # delete a file — no recycle bin, be careful

Permissions & running as root

  • sudo <command> — run a single command with administrator privileges
  • chmod +x script.sh — make a file executable
  • chown kali:kali file.txt — change who owns a file
  • Many Kali tools (packet capture, raw socket scans) need sudo because they touch the network stack directly

Getting help without leaving the terminal

  • man nmap — the full manual page for a tool
  • nmap --help — a quick summary of flags
  • whatis nmap — a one-line description
04

Updating packages

Kali is a rolling-release distribution — tools and security patches land continuously instead of once a year. Because you're relying on these tools to behave correctly (and securely), updating regularly matters more here than on a typical desktop OS.

The standard update routine

bash
$ sudo apt update              # refresh the package index
$ sudo apt full-upgrade -y     # upgrade everything, including dependency changes
$ sudo apt autoremove -y       # clean up packages nothing depends on anymore

Useful variations

  • apt list --upgradable — see what would change before you commit
  • apt search burpsuite — check whether a tool is available before installing it
  • sudo apt install <package> — install something new

Use full-upgrade, not upgradeapt upgrade refuses to remove packages, which can leave your system half-updated. full-upgrade handles dependency changes correctly. Reboot afterward if a new kernel was installed.

05

Navigating the Kali menu

Kali's Applications menu isn't organized alphabetically — it's organized by the phase of a penetration test where each tool is typically used. Learning this layout means you can find the right tool by thinking "what am I trying to do?" rather than remembering a specific name.

The core categories

  • Information Gathering — recon tools like Nmap, theHarvester, and DNS enumeration utilities
  • Vulnerability Analysis — scanners that flag known weaknesses, such as Nikto
  • Web Application Analysis — Burp Suite, OWASP ZAP, sqlmap
  • Password Attacks — Hydra, John the Ripper, Hashcat
  • Wireless Attacks — Aircrack-ng suite, Kismet
  • Exploitation Tools — the Metasploit Framework and related utilities
  • Sniffing & Spoofing — Wireshark, Ettercap
  • Post Exploitation — tools used after gaining access, like Mimikatz-style credential tools
  • Forensics — Autopsy, disk and memory analysis tools
  • Reporting Tools — utilities to help document findings professionally

Handy shortcuts

  • The "Top 10 Security Tools" menu surfaces the most commonly used tool in each category
  • Right-click any tool and choose "Add to Favorites" to pin it to the sidebar
  • The terminal icon on the taskbar is your most-used shortcut — learn its keybinding
06

Networking basics

Pentesting is fundamentally about sending network traffic to a target and understanding the responses, so a working mental model of IP addressing and VirtualBox's network modes is essential before you run your first scan.

Core concepts

  • IP address — a numeric identifier for a device on a network, e.g. 192.168.56.10
  • Subnet — a range of IP addresses grouped together, e.g. 192.168.56.0/24 covers .0 through .255
  • Gateway — the device (usually a router) that traffic passes through to leave the local network
  • DHCP vs static — DHCP assigns addresses automatically; a static IP is set manually and never changes

Checking your own network config

bash
$ ip a                   # show all network interfaces and their IPs
$ ip route                # show the routing table / default gateway
$ ping -c 4 10.0.10.20   # send 4 ping packets to a target

VirtualBox network modes — pick the safe one

  • NAT — the VM can reach the internet, but nothing else can reach the VM directly. Fine for updates, not for lab exercises.
  • Host-only Adapter — the VM can only talk to your host machine and other VMs on the same host-only network. This is what most projects in this hub use.
  • Internal Network — VMs can talk to each other but have zero access to the internet or your host — the safest option for running exploits against a target VM.
  • Bridged — the VM appears as a real device on your physical network. Avoid this for lab work; it's the mode most likely to accidentally scan devices you don't own.
07

Safe and legal pentesting

This is the most important module in the entire beginner track. Every tool taught on this hub can be used legally for defense and research, or illegally to cause real harm — the only difference is authorization. Read this module before you open a single tool.

The legal baseline

  • In the United States, the Computer Fraud and Abuse Act (CFAA) makes it a federal crime to access a computer system "without authorization." Most other countries have equivalent laws.
  • "I didn't cause any damage" is not a defense — unauthorized access alone can be a crime, regardless of intent or outcome.
  • Authorization must be explicit, in writing, and cover the specific systems you're testing — a verbal "sure, go ahead" is not enough for real-world work.

What "authorized" looks like in practice

  • Systems and VMs you personally own and control, on a network isolated from anyone else
  • Deliberately vulnerable practice targets built for this purpose: DVWA, Metasploitable, OWASP Juice Shop, VulnHub and HackTheBox machines
  • A real client or employer's systems, only under a signed contract with a defined scope, dates, and rules of engagement
  • Bug bounty programs, only within the exact scope published by the program

Good habits from day one

  • Keep attacker and target machines on an isolated Host-only or Internal Network, never Bridged, during practice
  • Document what you did and when — good notes are half of professional pentesting
  • If you ever stumble onto a real vulnerability by accident outside a lab, stop, don't exploit it further, and consider responsible disclosure to the vendor

Read before proceedingNothing on this site is legal advice, and laws vary by country and state. When in doubt, don't run a tool against anything you don't own or don't have written permission to test. See the full legal & safe-practice guidelines for more detail.
